<interfaces>
Consume MobileProviderRegistry and its createSemanticOperationLifecycle from Plan 04-01 rather than duplicating source order, labels, identity rules, capability copy, bounded validation, deadlines, cancellation, destroy behavior, or terminal settlement.

The controller-visible search identity is one object with sourceId, query, page, epoch, state, message, and rowsIdentity. Terminal transitions are idle, loading, content, empty, partial, cancelled, error, timeout, offline, entitlement, and unavailable. Settlement requires an exact current identity and loading state.

The existing MediaService.search(sourceId, options) facade and its legacy success/error or Promise-compatible cancellable handle remain the only search dispatch seam. The Bilibili detail/part model remains a nested variant owned by the selected Bilibili row; it is not the primary search state.

The semantic operation set remains exactly search, directory, media, lyric, and login. Plan 04-02 wires only the existing search seam into that route-free lifecycle. Directory, media, lyric, and login are still exercised with fake executors by the Wave-0 contract; if no pre-existing installed executor is supplied, each returns the exact terminal=unavailable record without touching MediaService, provider modules, or the Android bridge. Do not add a native RPC operation or broaden the native v2 terminal enum.
</interfaces>

| Boundary | Description |
|---|---|
| Registry projection to controller state | Capability truth determines whether a user action can start |

| Old page/request epoch to active shell | Late callbacks must not mutate the current layer |
