<interfaces>
The new classic-script global is MobileProviderRegistry. It owns immutable source descriptors, ordered primarySources and registrySources views, a projectCapabilities(sourceId, nativeMatrix, capabilityEpoch) projection, sourceForItemId(itemId), toTrackIdentity(sourceId, itemId, variant) validation, and createSemanticOperationLifecycle(options).

Android primary source order is exactly netease, kugou, kuwo, qq, bilibili. The separate desktop compatibility view preserves its existing netease, qq, kugou, kuwo, bilibili, migu, taihe order and provider instances. Registry-only Android entries are migu and taihe. Existing track identity examples remain opaque and unchanged: netrack_42, kgtrack_HASH, kwtrack_123, qqtrack_abc, bitrack_123, and bitrack_v_BV1xx411c7mD-101.

The only capability fields admitted from native truth are search, directory, detail, media, lyric, manualLyric, fallback, login, and permission. UI-only projection adds declared display name, account requirement/state, availability, retryability, safe reason, and identity variants without retaining the native object.

The route-free semantic lifecycle admits exactly search, directory, media, lyric, and login. Its immutable request identity has exact keys operation, sourceId, requestId, pageEpoch, deadlineAt, and payload; requestId and deadlineAt are lifecycle-generated rather than accepted from provider/page payload. Reuse existing contract ceilings: requestId is 1-128 characters, pageEpoch is 0-2147483647, deadline duration is 1-30000 ms, search keyword is at most 256 UTF-8 bytes, page is 1-1000, result collections are at most 50 rows, semantic text fields are at most 512 characters, and lyric content is at most 256 KiB. Exact-key per-operation validators reject recursive/unbounded data and all URL, header, cookie, token, signed-candidate, local-path, native-object, and raw-error fields. The immutable semantic terminal has exact keys operation, sourceId, requestId, pageEpoch, terminal, status, code, and result, with terminal limited to ok, cancelled, timeout, error, or unavailable. An ok terminal contains only a shallow, operation-validated result within the same row/text/lyric bounds; every non-ok terminal has result=null and a closed safe code from OPERATION_UNAVAILABLE, CANCELLED, DEADLINE_EXCEEDED, INVALID_REQUEST, INVALID_RESPONSE, or PROVIDER_ERROR. This page-side contract adapts existing callbacks/promises but does not change the native RPC v2 operation or terminal enums.
</interfaces>
