  <behavior>
    - Queued cancel removes/cancels the queued Future and emits one `cancelled` terminal result.
    - Running cancel sets the terminal guard, disconnects the active connection, interrupts/cancels the Future, and emits one `cancelled` result even if transport later reports an error.
    - Timeout uses terminal error code `timeout`; it disconnects work and cannot also settle as cancelled or network failure.
    - Destroy cancels every registered call and suppresses all reply-proxy posts after teardown.
    - Duplicate request identity is rejected; duplicate/late settle attempts report `already-settled` internally and emit nothing.
    - Retry performs at most two total attempts for idempotent transient failures, uses bounded backoff under the same deadline, and stops immediately on cancellation.
  </behavior>
  <action>
Create pure/package-private `BridgeRequestRegistry` keyed by immutable `(pageEpoch, requestId)`. Its `CallHandle` owns an atomic terminal guard plus optional Future and active `HttpsURLConnection` references. `register` rejects duplicates, `cancel` atomically chooses `cancelled`, cancels queued/running work and disconnects transport, `settle` selects exactly one terminal result, and `cancelAll` handles WebView destruction. Return internal `SettleResult` values so `AndroidHttpBridge` posts only the winner; do not treat a caught disconnect exception as another terminal event.

Create pure `BridgeRetryPolicy` with at most two total attempts, bounded backoff, operation deadline, and a closed transient set: network I/O plus HTTP 429/502/503/504. Do not retry redirects, TLS failures, provider/schema/permission/invalid-part/unsupported-codec errors, or any cancelled/expired call. Inject time/sleep or express decisions as pure values so JUnit does not actually wait.

Wire both helpers into `AndroidHttpBridge`: register before executor submission, retain the `Future`, attach/detach the active connection, implement `rpc.cancel` against the target identity, map deadline expiry distinctly, and cancel all on `destroy`. Maintain the bounded queue and origin check. Write lifecycle tests first with fake Future/disconnect actions and controlled races, then implement until each case proves one terminal winner.
  </action>

    - Retry attempts and delays are mechanically capped and observable without sleeping in unit tests.
    - Registry/error diagnostics contain stable state and bounded identity only, never URL, headers, cookies, provider body, or exception text.
