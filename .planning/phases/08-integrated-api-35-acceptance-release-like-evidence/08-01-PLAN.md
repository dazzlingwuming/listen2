<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Source/dependencies -> APK | Build tooling can package stale, legacy, debug or malicious content. |
| Signing material -> candidate | Development signing must remain distinguishable from formal release authority. |
| Raw command/artifact -> evidence | Paths, credentials, URLs or payloads could leak into retained reports. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-08-01-01 | Tampering | Build/reproducibility | high | mitigate | Locked inputs, two clean builds, byte hash equality and entry-level mismatch failure. |
| T-08-01-02 | Spoofing | Signer/release label | high | mitigate | `apksigner` certificate digest, development-signed filename/status and unsigned formal release. |
| T-08-01-03 | Information disclosure | APK/evidence | critical | mitigate | Phase 7 scanner, APK inventory scan, closed redacted schema and canary self-tests. |
| T-08-01-04 | Elevation | Manifest components | high | mitigate | Merged-manifest allow-list, cleartext/debuggable/exported/provider/service checks. |
| T-08-01-05 | Denial of service | Build scripts | low | accept | Serial bounded commands, explicit environment and cleanup traps make a local failure recoverable. |
| T-08-SC | Tampering | Package installs | high | mitigate | No new npm/pip/cargo or Gradle dependency is installed; existing locks and cached coordinates are used. |
</threat_model>
