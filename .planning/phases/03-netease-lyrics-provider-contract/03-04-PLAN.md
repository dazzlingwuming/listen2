<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Page lyric intent → persistence port | Untrusted identity/content/revision requests durable mutation. |
| Repository → Room file | Semantic state crosses the durable on-device boundary and survives process recreation. |
| Room restore → page reply | Corrupt/stale records must not become current or expose raw database errors. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-13 | Tampering | `LyricRepository` writes | high | mitigate | Exact identity, expected revision, idempotency token, bounds validation, and one Room transaction. |
| T-03-14 | Information disclosure | Room schema/content | high | mitigate | Semantic allow-list, bounded content, forbidden column/value scans, no raw database errors in replies. |
| T-03-15 | Denial of service | Lyric content persistence | medium | mitigate | 256 KiB per text/512 KiB combined bounds, bounded metadata/timestamps, key-local corruption recovery. |
| T-03-16 | Repudiation | Manual clear/revision transitions | low | accept | Monotonic semantic revision and transition token provide deterministic replay evidence; local personal app has no remote audit requirement. |
| T-03-SC | Tampering | Package installation | low | accept | No package install; existing Room 2.8.4 and schema export machinery are reused. |
</threat_model>
