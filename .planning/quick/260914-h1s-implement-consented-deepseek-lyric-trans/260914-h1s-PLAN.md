<locked_decisions source="approved audit and project constraints">
- D-01: Canonical implementation target is mobile/ React Native. Legacy android/ and desktop code supply behavior and test-vector references only; do not wire the old WebView bridge.
- D-02: API-key plaintext never enters JavaScript: configure launches a native Android password-entry surface which saves directly to Keystore-backed storage and returns only status. Ciphertext, Cookie, caller headers, arbitrary URL, prompt envelope, raw provider body, and raw exception text remain native-only or are discarded. The RN module is an allow-listed semantic surface, never a generic networking bridge.
- D-03: Fixed DeepSeek contract remains compatible with the desktop implementation: HTTPS api.deepseek.com/chat/completions, model deepseek-v4-flash, prompt version deepseek-lyrics-v2, target zh-CN, and exactly native-owned `Authorization: Bearer <native key>`, `Content-Type: application/json`, `Accept: application/json`, and `User-Agent: Listen2Android/1` headers. Callers cannot add or override headers; body/prompt, redirects, bounds, and errors remain fixed.
- D-04: Six consent fields plus acceptedAtEpochMs are per-request ephemeral data. No translation request is initiated automatically; force refresh always requires explicit network consent.
- D-05: Request bounds are separate from the larger display parser bounds: UTF-8 lyric input <=64 KiB, <=400 timed lines, source line <=500 characters, title/artist <=256, style <=1200, request <=256 KiB, response <=128 KiB, translated line <=1024, exact unique line IDs, no controls/newlines, and at most one emoji per song.
- D-06: Define `lyricHash = SHA-256(normalized timed LRC)` and `trackHash = SHA-256(provider + "\n" + sourceTrackId + "\n" + lyricHash)`. The native app-private lyric-cache-v1 atomically keys and records trackHash plus model, prompt fingerprint, target, title, artist, and style; the API key is never part of the key or entry. Equal lyrics on a different trackHash cannot hit or apply. Cache hit is allowed without network; cache miss is not network authorization.
- D-07: NetEase and QQ are the first eligible mobile lyric sources. Bilibili, Kugou, Kuwo, local tracks, and any source whose provider capability says lyric=false return a truthful unavailable result; do not fabricate lyric text.
- D-08: Existing mobile backup/export remains metadata-only. DeepSeek key, settings, consent, lyric text, translation cache, and provider transport values are excluded by construction and tested explicitly.
</locked_decisions>
