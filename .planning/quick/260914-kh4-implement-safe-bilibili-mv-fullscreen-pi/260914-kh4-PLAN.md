<locked_decisions source="approved audit and project constraints">
- D-01: `mobile/` React Native is the only implementation target; desktop and legacy
  `android/` files are read-only behavioral references.
- D-02: RNTP is the only audio/MediaSession/audio-focus owner. MV uses a separate
  video-only native player, is muted, never requests audio focus, and never registers
  a MediaSession or audio foreground service.
- D-03: JS sends only semantic `{bvid,cid,qualityId?,preferredCodecs?,forceRefresh?}`
  requests. Native returns an opaque MV handle and safe public metadata; signed video
  URLs, headers, deadlines, cookies, and raw provider data stay native and in-memory.
- D-04: Native verifies CID belongs to BVID and never substitutes another page. Quality
  IDs are restricted to the desktop-known allow-list (16, 32, 64, 74, 80, 112, 116,
  120, 125, 126, 127) or `auto`; arbitrary qn/fnval/query input is forbidden.
- D-05: Video errors, codec/entitlement failures, and MV refresh exhaustion disable
  only MV and leave the current RNTP audio occurrence playable and unchanged.
- D-06: Audio fallback is bounded and typed. Transient audio failures may perform a
  single native re-resolve/validated retry while preserving one RNTP queue; login,
  membership, region, DRM, cancellation, and unsupported codec errors do not retry.
  The pre-existing audio compatibility URL handoff remains function-local to the one
  RNTP load call and is never stored, dispatched, cached, backed up, or logged. If a
  future interpretation forbids even that RNTP-required handoff, stop and escalate
  rather than inventing a second player or a generic bridge.
- D-07: Fullscreen/PiP/rotation/process recovery persist only semantic MV identity,
  selected quality, position, and play intent. The MV handle is volatile and is never
  written to Redux persistence, AsyncStorage, backup, `Bundle`, or process snapshots.
  Signed transport is re-resolved after recreation and is never persisted.
- D-08: Do not add `react-native-video` or direct imports of RNTP's transitive old
  ExoPlayer. Reuse the already assessed Media3 line only as a new video-only stack,
  subject to offline dependency resolution; no `media3-session` dependency is needed.
- D-09: No APK build, device run, live Bilibili request, credential use, merge, or
  deployment is part of this quick task. Do not add unverified `androidTest` sources;
  emulator/instrumentation evidence belongs to a later device-validation phase.
</locked_decisions>
