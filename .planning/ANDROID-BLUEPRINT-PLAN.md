# Android 全功能蓝本执行计划

**批准来源：** 用户于 2026-09-08 明确要求先连续完成全部主要功能，再统一生成 APK 验收。
**基线：** `origin/main@6c5cf119943412f06f71b792d1379147673b15a7` 与当前 Android 分支 `5de861e4430bc9dd0a0d06f2be79763eb0576075`。
**交付单元：** 一个完整 Android 功能蓝本，不按单个功能生成 APK。

## 目标

在保留现有 Media3 单一播放所有者、Room 持久化和封闭 WebMessage/RPC 安全边界的前提下，把桌面端主要用户功能一次性接入手机导航和 Android 平台能力；完成代码与模块级快速测试后，再集中构建第一版整体验收 APK。

## 本轮必须覆盖的用户能力

- 手机导航、首页、发现/搜索、音乐库、设置和完整播放器/歌词。
- Bilibili、网易云及能力矩阵中的其他来源；未通过真实路由验证的来源必须显示明确不可用或降级状态。
- 歌单、收藏、创建/重命名/编辑/删除/排序及下一首队列。
- 账户页和 Bilibili 扫码登录/会话/退出的安全 Android 等价入口。
- SAF 本地音乐、标签/封面/时长/LRC 与授权修复。
- 歌单备份导出、预览、合并导入和明确确认的覆盖导入。
- 听歌历史、年度回响、关闭/导出/清空。
- 缓存、下载、离线播放、容量和 LRU 管理。
- 音质、分 P、MV/全屏/PiP、音效、真实可用时的可视化与响度降级。
- DeepSeek Key 安全保存、测试/删除、明确同意和歌词翻译。
- 手机设置、系统返回、安全区、键盘、旋转、字体缩放和无障碍入口。

## 工作流与责任边界

### A. 手机产品表面与共享前端

负责四主导航和全部二级页的手机布局、状态、动作入口、降级文案及前端契约测试。优先复用当前共享 AngularJS/controller/provider 逻辑，不复制旧 React Native 运行时。

### B. Android 本地数据与文件能力

负责歌单/收藏、SAF 本地媒体、备份、历史/年度统计、缓存/下载目录和设置的 Android 数据合同、持久化及纯 JVM 测试。页面只接收脱敏 DTO，不接收原始路径或文件句柄。

### C. Android provider、账户与高级播放能力

负责版本化 provider/account/media RPC、Bilibili/网易云的授权路径、Media3 rendition/分 P/MV/PiP/效果能力投影及稳定错误状态。不得开放任意 URL、Header、Cookie 或签名材料。

### D. 主线集成

由主 Agent 统一连接 Activity、Manifest、Gradle allow-list、前端 bridge、跨模块状态和回归测试；处理跨工作流冲突并维护 provider live truth。

## 验证节奏

1. 开发期间只运行当前模块的 JVM/Node/静态契约快速测试，不运行 `assembleDebug`，不生成 APK，不提交。
2. 各模块合入后运行跨模块快速测试并修正接口差异。
3. 全部主要功能代码完成后，才调用 `$run-local-ci` 执行仓库规定的完整门禁。
4. 门禁通过后集中生成并安装一次 Debug APK，在 API 35 模拟器做整体验收。
5. 外部 provider 或真实账号无法完成的路径保留 `BLOCKED / not verified`，不以 fixture、构建或页面存在替代。

## 完成标准

- 上述主要功能均有手机可达页面和真实实现或明确、可操作的不可用状态。
- 不存在“点击后无反应”、无限加载或把失败显示为空成功的入口。
- 开发期未进行逐功能 APK 循环。
- 首个新 APK 只在整体功能蓝本代码完成后生成，并作为整体验收包交付。
