# 桌面播放与歌词网络诊断结论

调查日期：2026-10-20，Asia/Shanghai。范围为已安装的 Electron 桌面版，Android 不在本轮范围。

## 结论

当前代理的默认 DNS/Fake-IP 网络路径与已复现的网易、酷狗连接失败有关。相同 Electron 客户端、相同请求参数和请求头下，使用默认 Fake-IP 解析会连接关闭，限定到真实公网地址后成功。仅关闭探针内的显式 HTTP 代理仍然失败。

这支持优先排查代理的 Fake-IP、TUN 和音乐域名分流。尚未定位代理内部哪条规则或公司网络的哪个环节造成故障，也未捕获用户原始歌曲的音频 CDN 失败记录，因此不能声称所有播放失败已经找到了同一个根因。

QQ 在真实公网地址路径下仍连接复位，属于仍需单独定位的连接问题。LRCLIB 当前可用。酷狗某歌词查询成功但返回零候选，说明无匹配结果与网络失败需要分别处理。

## 搜索与播放的关系

```text
歌曲搜索 → 获取歌名等资料
点击播放 → 获取可用播放地址 → 连接音频服务器 → 解码和播放
歌词检索 → 请求各歌词来源 → 选择匹配的同步歌词
```

这些步骤使用的接口和域名不同。搜索成功不能证明播放地址、音频服务器和歌词来源都可用。原始播放失败具体位于哪一步仍待运行时证据。

## 现状核对

- 安装版为 `/Applications/Listen1.app`，版本/build 2.35.4；关键运行文件与已安装的 DeepSeek 修复树 `bc267d3`（含 `c9ce651`）匹配。
- 系统代理已启用，应用持久化代理模式为 system；隔离 Electron 探针也解析到当前本机代理。
- QQ、网易、酷狗和 LRCLIB 的八个代表域名在系统 DNS 中均返回 `198.18.0.0/15` Fake-IP 地址。Fake-IP 是代理可采用的工作模式，本身不等于解析损坏；机制参见 [Mihomo DNS 官方文档](https://wiki.metacubex.one/config/dns/)。
- 桌面代码存在多种网络路径：普通歌曲搜索/播放地址请求走 renderer XHR/Chromium；外站歌词经独立 Node HTTPS 公网地址请求，网易歌词经独立 Chromium 验证 session 和本地直连 tunnel。应用系统代理设置不直接控制这些专用歌词出口。相关源码为 `app/main.js`、`app/lyricDirectTransport.js`、`app/neteaseVerificationSession.js`。

## 受控网络对照

以公开的网易搜索和酷狗歌曲搜索请求作为代表；均使用 Electron 32.3.2、相同 URL/参数/请求头、匿名请求、默认启用的证书校验。使用独立 profile，没有复制用户账号或验证状态。

| 探针路线 | 网易 | 酷狗歌曲搜索 |
| --- | --- | --- |
| system 代理 + 默认 DNS | `ERR_CONNECTION_CLOSED` | `ERR_CONNECTION_CLOSED` |
| direct 模式 + 默认 DNS（已确认 Fake-IP） | `ERR_CONNECTION_CLOSED` | `ERR_CONNECTION_CLOSED` |
| direct 模式 + 仅探针进程的真实公网 host-map | HTTP 200，API code 200 | HTTP 200，5 条结果 |

第三行的完成事件确认连接地址与所提供的公网映射匹配。第二行解析确认返回 Fake-IP。透明 TUN 或其它网络接管仍可能作用于这些连接；此对照没有关闭它们，也没有改变系统配置。

其它有限样本：

- QQ：Electron 系统路线连接关闭；安装版歌词直连模块观察到连接复位；curl 固定公网 A 后仍在 TLS 阶段失败，未取得 HTTP 响应。
- LRCLIB：Electron 系统路线与安装版歌词直连路线均返回 20 条同步歌词候选。
- 安装版网易专用歌词路线：API code 200，没有复现历史记录里的验证码挑战。
- 安装版酷狗专用路线：歌曲检索 5 条；该样例歌词检索 HTTP/API 成功但候选为零。
- DNS 查询存在波动：首轮 AliDNS 触及每次 2 秒预算，Google 回退成功；后续 AliDNS 也能正常响应。未据此认定其为全部故障根因。

## 建议的后续处理

1. 先针对实际代理客户端的音乐域名检查 Fake-IP/TUN 和分流规则，以 1～2 首歌曲对照真实解析路线。修改前保存当前配置，按同一歌曲、同一网络复测。
2. 捕获一次原始播放失败的安全诊断：来源类别、获取地址或媒体加载阶段、网络错误码和 CDN 域名；据此决定网络规则调整还是桌面代码修复。
3. QQ 的连接复位继续独立验证。歌词请求应明确展示连接失败、验证要求或零匹配，避免都表现为“搜不到”。

## 覆盖限制与变更范围

本轮完成只读诊断。没有修改产品源码、已安装应用、系统 DNS/代理，没有重装或重启用户应用。没有播放原始失败歌曲、修改代理规则或实测音频 CDN；播放故障的完整根因与修复效果仍为 **not verified**。用户提及 QQ/网易/酷狗究竟指播放平台还是歌词来源的补充问题尚未得到回复。

临时 Electron 探针仅在登记的独立 runtime 中运行；验收本报告后由任务入口清理，过程和清理凭据记于同目录任务记录。
