# macOS 直接安装与签名约定

最后更新日期：2026-10-21

状态：已确认，适用于 Listen2 桌面项目后续构建、候选验收与安装协作。

## 用户决定与范围

项目有意维持 macOS 未签名 DMG 直接安装方式。该决定覆盖后续 Codex/Agent 的构建和安装辅助行为；不得因工具习惯或只读签名检查失败而自动改变发布方式。本约定只记录此选择，不代表 macOS 对每台设备的启动结果。

## 构建和安装规则

- macOS 构建保持 `CSC_IDENTITY_AUTO_DISCOVERY=false`，不配置 Developer ID 签名或 Apple 公证分发。
- 不对发布制品或本机已安装副本执行 `codesign --sign`、重签、补签或签名修复；不新增证书、钥匙串信任项或其他签名基础设施。
- `codesign --verify` 等只读检查可以执行并如实记录。对于有意未签名的原包，验证失败本身不触发修复，也不能单独阻断已经核对的原包安装。
- 安装核验依据：受信来源、DMG/应用制品 SHA-256、bundle 版本与 ID、目标架构，以及目标系统上的实际启动结果。不要以重新签名替代这些检查。
- 若操作系统实际阻止启动，保留并报告系统显示的原始错误和环境。等待用户决定后续操作；Agent 不自动修改 Gatekeeper/其他安全设置、不移除 quarantine，也不采用绕过措施。
- 不推断签名状态与密码提示之间的必然因果；只记录实测系统输出。
