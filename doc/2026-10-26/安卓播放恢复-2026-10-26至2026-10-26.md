# 安卓播放恢复与操作响应

用户反馈 `2.35.7-android.2` 所有歌曲无法播放，并且切歌、操作不够流畅。任务登记 `android-playback-20261026`，基线 `927031b`。

已复现：电脑原生解析器与 Android 模拟器中，搜索成功，旧视频详情接口 `/x/web-interface/view` 返回 HTTP 412，导致分 P 解析失败。相同公开视频 `BV1nw86zuE9T`、`BV1r7411p7R4` 的 `/x/player/pagelist`、音频清单返回成功，CDN 实际返回 HTTP 206 与音频字节。只记录公开曲目标识、状态和字节数，未保存请求凭据或临时播放地址。

修复方向：读取播放需要的有序分 P 列表；保留 CID、响应码和音频地址验证；首次默认分 P 的已验证信息用于后续播放，减少重复请求。网络解析从播放命令及存储队列移出，连续切歌只保留最新待执行请求；解析期间暂停的意图继续保留。来源拒绝请求与歌曲无音频分别提示。

又发现一处直接影响操作的错误：本地成功响应的 HTTP 状态为 0，桥接重试逻辑把它当成网络失败，再次执行已经成功的命令。模拟器中创建歌单实际成功却返回 INVALID_INPUT，播放歌单也会重复启动。改为只对允许重试的只读网络操作处理真正的瞬时失败，成功结果和写入命令立即返回，不重放。

本次模拟器采用已有设备的只读运行，不更改其保存状态；手机尚未连接。

连续操作验证补充发现：部分公开音频返回海外主节点 `upos-hz-mirrorakam.akamaized.net`，旧白名单丢弃该节点；仅剩的国内备用节点偶发 HTTP 567 时无法继续。新增这个精确主机的 HTTPS/443 支持，不放开其他 Akamai 租户，保留签发地址与过期校验。模拟器已观察到 HTTP 567 后切换剩余节点并播放成功。

播放进度事件还可能先于刚发送的控制命令到达原生层，触发 STALE_REVISION。仅对此明确未执行的拒绝，等待更新快照后对传输控制重试一次；成功、未知结果和歌单写入均不重放。等待快照增加上限与 16 毫秒间隔，停止零延迟忙轮询。加载时根据播放意图提供暂停/播放按钮，已暂停的缓冲不再显示正在解析。

验证完成：236 项 JVM、23 个共享前端脚本、6 个专项脚本通过。模拟器中创建歌单返回成功；两个没有 CID 的真实条目均正常播放，切歌后立即暂停并保持在 0 毫秒，随后恢复播放成功。两次命令确认耗时约 18 / 30 毫秒，不代表音频加载耗时。正式 R8 APK 已独立安装，通过实际界面搜索、分 P 播放，系统会话 PLAYING 且进度增加、无错误。模拟器声音输出关闭，未做耳听或实体手机长时间锁屏验收。

交付版本 `2.35.7-android.3` / `2350703`，稳定签名保持一致；APK 大小 4,298,698 字节，SHA-256 `ee92bd1675a528fc371b731638ea37141f17c9136f26da79d058dea60fe623d6`。制品与发布回执保存于 `dist/releases/v2.35.7-android.3/`，验证日志与截图在 `output/`，均不打入 APK。详细范围见 `android/VALIDATION.md`，既有 3 个旧前端失败仍如实保留。
